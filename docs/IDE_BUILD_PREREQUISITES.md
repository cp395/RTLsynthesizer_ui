# Gowin IDE build prerequisites

`tang_mega_60k_hdmi.gprj` contains a **candidate** `GW5AT-60 / GW5AT-LV60PG484A`
device entry solely so Gowin IDE can open the project. It is not a confirmed
board configuration and an IDE project opening successfully is not a synthesis,
pinout, timing, or hardware-validation result.

Before using **Synthesize**, **Place & Route**, or **Generate Bitstream** in the
GUI, manually replace or confirm all of the following from the board schematic,
PCB revision, and device marking:

- Complete FPGA part, package, speed/temperature grade, and device version.
- Oscillator frequency, input pin, and IO-bank voltage.
- HDMI architecture. The checked-in top supports only
  `PARALLEL_RGB_EXTERNAL_TX`; `DIRECT_TMDS` is not implemented.
- HDMI transmitter part, I2C address, reset/power/HPD/interrupt wiring, RGB
  order, sync polarity, and every HDMI/I2C pin. The checked-in top is coupled
  to the ADV7513 controller and address; another transmitter requires a
  replacement controller/top before it can be selected.
- IO standards, bank voltages, and the complete constraint file.
- A PLL generated by Gowin PLL Wizard for the confirmed FPGA, input clock, and
  target pixel clock. Set the matching `PLL_*` fields in `board_config.tcl` and
  replace `rtl/Gowin_rPLL.v` before setting the confirmation flags to `1`.

The command-line scripts and generated `build_generated.tcl` call
`require_board_config`; they intentionally stop while these values are
unconfirmed. The IDE does not consume that Tcl preflight automatically, so a
GUI build must follow the checklist above and must still pass synthesis,
place-and-route, static timing analysis, bitstream generation, programming, and
real-display verification before it can be called a deliverable.
